# NeoPad 金融工具研究与实施计划

日期：2026-10-12。状态：资金工具、通用债券、个人贷款、正逆回购与笔记集成已实现；持有期收益与 XIRR 已实现并通过桌面验收，快捷键改为 Shift+F1；当前本地测试版本为 0.7.5，国内 Wind / 中债口径待核验。实际使用说明见 [金融工具](financial-tools.md)。

## 1. 目标与已确认需求

为经常使用金融计算的工作场景提供一个随时可打开的本地工具面板，并将计算的输入、口径和结果保存为普通 Markdown 笔记。

用户已确认：

- 高频需求为利息、复利、折现、年金，以及债券价格、收益率和久期。
- 债券需要同时服务国内人民币债券和通用测算 / Excel 对照。
- 入口和使用方式参考 F6 提醒列表。
- 后续已授权实施；国内模式的对照目标确认为 Wind / 中债估值。

产品判断：与 NeoPad 的小窗口、快捷键、本地笔记定位相容。价值来自快速测算和留下可复核记录；主要成本在计算口径和数值验证，而不是面板本身。

## 2. 研究结论与证据边界

### 2.1 借鉴金融计算器的变量组织，不照搬按键操作

TI BA II Plus 将资金时间价值、现金流、债券等分成工作表，区分支付频率 P/Y 和复利频率 C/Y。NeoPad 可借鉴这种组织方式，以有标签的表单呈现，并在结果旁持续显示有效口径。[TI 官方指南](https://education.ti.com/html/eguides/financials/pdfs/EN/BA-II-PLUS_EN.pdf)、[P/Y 与 C/Y 说明](https://education.ti.com/en/customer-support/knowledge-base/financial-calculators/general-information/11262)。

### 2.2 通用金融函数可以对照 Excel，但需要明确适用范围

Excel FV / PV 使用每期利率、总期数、期初或期末支付，并采用现金流正负号约定。EFFECT 用于名义年利率和有效年利率换算。这些文档适合作为通用模块的参考；NeoPad 的友好输入可以使用“投入 / 收取”方向，内部再转为现金流符号。[FV](https://support.microsoft.com/en-us/excel/functions/fv-function)、[PV](https://support.microsoft.com/en-us/excel/functions/pv-function)、[EFFECT](https://support.microsoft.com/en-us/excel/functions/effect-function)。

Excel PRICE / YIELD 的参数包含结算日、到期日、票息、付息频率、偿还价值和计息基准，最后一期另有分支。它们是通用债券模式的对照目标，不应直接当作国内报价算法。[PRICE](https://support.microsoft.com/en-us/excel/functions/price-function)、[YIELD](https://support.microsoft.com/en-us/excel/functions/yield-function)。

### 2.3 国内模式需要单独的口径规格

中国银行明确区分净价、应计利息和交易全价，三者必须在界面中分开。[中国银行柜台债券说明](https://www.boc.cn/cbservice/cb4/cb42/200807/t20080701_899.html)。

检索发现，银发〔2004〕116 号和银发〔2007〕200 号收益率计算标准文件已列入中国人民银行公告〔2023〕第 4 号的废止目录。不能把网上常见的历史公式标为现行强制标准；废止本身也不能推导出数学公式失效或实务完全停用。[人民银行官方文告，印刷页 3–4，PDF 第 5–6 页](https://www.pbc.gov.cn/chubanwu/114566/114579/4940535/5093963/2023101214213262517.pdf)。

交易中心 2020 年估值手册中的固定利率债券估值使用即期曲线和价差。单一 YTM 测算不能宣称复现交易中心的曲线估值。[CFETS 债券估值手册，印刷页 12](https://www.chinamoney.com.cn/dqs/cm-s-notice-query/fileDownLoad.do?contentId=1533995&mode=open&priority=0)。

目前已确认上述边界，尚未确认全部现行国内个券报价公式、最后一期处理和节假日规则。实施阶段必须补充当前业务 / 算法说明及可复核算例；国内模式的启用以此为前置条件。

### 2.4 计息基准与收益率口径应分别建模

Act/Act ICMA 需要付息日程，Act/Act ISDA 按日历年区分 365 / 366；两者不能合并成一个含糊的“实际 / 实际”。30/360 也存在不同变体。[OpenGamma Strata 官方计息基准说明](https://strata.opengamma.io/day_counts/)。

设计因此分别保留：计息基准、收益率口径、付息频率、日程规则。只有验证过的组合进入 UI。

## 3. 首轮范围

首轮分为资金模块和债券模块两个交付批次。通用债券与国内债券均属于目标，后者必须完成口径验证才可标记可用。

| 模块 | 首轮内容 | 输出 | 暂缓内容 |
| --- | --- | --- | --- |
| 利息 | 单利、复利；期限输入与日期输入分开 | 利息、终值、期限口径 | 变动利率、分段计息 |
| 利率换算 | 名义年利率、有效年利率、周期利率 | 换算结果、复利频率 | 连续复利、多种收益率混合转换 |
| 现值 / 终值 / 年金 | 单笔与等额规则现金流；求 PV、FV 或 PMT | 结果、支付频率、期初 / 期末 | 反求 RATE、NPER，不规则现金流 |
| 债券通用模式 | 规则付息、固定利率、到期一次还本的非含权债券；价格与 YTM 互算 | 净价、全价、应计利息、现金流、久期、DV01 | 不规则首尾期、浮息、含权、提前还本 |
| 债券国内模式 | 优先国债、政金债中的规则付息固定利率品种；按已核验的国内规格实现 | 同上，显示具体口径和来源版本 | 存单、贴现、特殊兑付规则、交易日历自动推断 |

零息品种后续独立加入，不用“票息填 0”替代对市场规则的核验。贷款、NPV、IRR / XIRR、组合分析等在高频需求之后排序。

首轮全离线、手工输入，不依赖 AI、行情接口或券种数据库。只保存明确插入笔记的计算记录。

## 4. 面板与操作

### 4.1 入口与布局

- 工具菜单增加“金融计算器”，建议本地快捷键 `Shift+F1`；F6 保留提醒。
- 使用类似提醒列表的主窗口内面板，按需加载，不新增窗口或常驻侧栏。
- 左侧分组导航：债券类与资金类；工具为债券收益、利息、利率换算、现值 / 年金。右侧分组表单与固定操作栏，默认打开到期收益率。
- 默认 720 × 520 时使用参数 / 结果两区；420 × 360 最小窗口改为纵向可滚动布局，操作按钮始终可访问。
- 小窗口分类采用紧凑选择器，不强行挤入四个标签和长说明。
- 延续明暗主题、中英语言和现有控件风格。

```text
金融计算器       [类别选择]                     [关闭]
----------------------------------------------------
[求解目标]      [计息 / 收益率口径]
参数名称 [输入值] [单位]       参数名称 [输入值]
参数名称 [输入值]              [计算] [重置]
----------------------------------------------------
主要结果
口径摘要                 [展开公式 / 现金流明细]
----------------------------------------------------
[复制结果]   [复制完整记录]   [插入当前笔记]
```

### 4.2 输入与结果状态

- 百分比字段旁固定显示 `%`；输入 `3` 表示 3%，展示归一后的值。不得复用编辑器中将 `%` 当作取余的表达式解析器。
- 本金与面值输入以元 / 基本货币单位为主；单位换算必须显式选择。债券价格默认按每百元面值，持仓面值单独用于金额 / DV01 缩放。
- 每期金额、每年支付次数、每年复利次数分别填写；支付频率与复利频率不同时按有效周期利率换算。
- 计算按钮或 Enter 触发求解。任何参数修改都会立即使旧结果失效，复制 / 插入按钮禁用，避免保存过期结果。
- 空值、非法百分比、非整数期数、无效日期、计算域错误都有字段提示；错误不显示 0、NaN 或 Infinity。
- 面板关闭再打开保留本次启动内的输入，重启清空；首轮不自动持久化金融输入。
- Esc 关闭面板并恢复编辑器焦点；Tab 在面板内移动，Ctrl+Tab 不切换底层笔记。
- 面板打开时阻止笔记切换、新建、删除、归档、打开文件等底层动作；与其他主面板互斥。显式确认对话框优先级更高。

### 4.3 与笔记结合

- “复制结果”提供精简文本；“复制完整记录”与“插入当前笔记”使用同一 Markdown 格式。
- 完整记录含工具名称、输入、计息 / 收益率口径、现金流方向、结果、精度和计算引擎版本；时间只作记录信息，不影响金融日期算法。
- 插入为一次可撤销的编辑事务；默认在打开面板时捕获的光标位置插入，不替换原选区。若目标文档 / 内容版本已变化，拒绝插入并保留复制选项。
- 编辑、分屏模式可插入；纯预览模式只允许复制，并提示切换到可编辑模式。
- 原有自动保存与冲突检查负责落盘。保存失败时保留编辑内容并显示失败，不能把“已插入”表示成“已保存”。
- 结果自然获得 Markdown 预览、PNG / PDF 导出能力，不增加独立报告系统。

## 5. 计算规格

### 5.1 单利、复利和日期

统一内部利率为小数；界面百分比在边界转换一次。

- 单利：`I = P × r × t`，`FV = P + I`。
- 复利：`FV = P × (1 + j/m)^(m×t)`；首轮限定完整复利期数，拒绝日期跨度隐含的零头期算法。
- 日期单利支持 `Act/365F`、`Act/360`、`Act/Act ISDA`，默认明确显示 `Act/365F`，不称为所有产品的统一默认。
- 日期计算使用纯日期，不转为 UTC 时间戳；采用起日计入、止日不计入的区间规则，显示实际天数。
- 日期复利和零头期利息首轮不开放，后续先定义规则再增加。

### 5.2 利率换算与等额现金流

设名义年利率为 j，年复利次数为 m，年支付次数为 p：

```text
有效年利率 EAR = (1 + j/m)^m - 1
有效支付周期利率 i = (1 + j/m)^(m/p) - 1
普通年金终值系数 = ((1+i)^n - 1) / i
普通年金现值系数 = (1 - (1+i)^(-n)) / i
先付年金系数 = 普通年金系数 × (1+i)
```

PV、FV、PMT 的通用内部关系采用收款为正、付款为负：

```text
PV × (1+i)^n + PMT × (1+i×b) × ((1+i)^n-1)/i + FV = 0
b = 0 为期末支付，b = 1 为期初支付
```

界面通过“方向 + 正金额”转为符号，不把符号错误隐藏成绝对值。零利率使用解析极限；零期数、近零利率和非有限数值需显式处理。负利率只在数学域成立且有对照测试的工具中支持；Excel 不支持的输入不纳入 Excel 一致性承诺。

### 5.3 通用债券

- 首轮以 Excel PRICE / YIELD 规则付息模式为明确目标，先支持 `Actual/Actual` 债券日程模式与 `US (NASD) 30/360`；细节与兼容边界写进规格，不能仅凭名称映射到 Strata。
- 输入结算日、到期日、上一 / 下一付息日或可预览的规则日程、年票息、年付息频率 1 / 2 / 3 / 4（3 为通用扩展）、每百元偿还价值、求解目标及价格或 YTM。
- 从到期日锚定日程，区分保持原日号与月底规则。计算后展示自动日程供用户核对；显式输入与规则日程不符时拒绝计算，不推断首尾短长周期。
- 结算日必须早于到期日；结算恰在付息日时明确是否包含当日现金流，并保持应计利息口径一致。
- 保留 Excel 最后一期的定价分支。久期与 DV01 必须由同一定价函数和收益率口径派生；不得对最后一期机械套用多期复利关系。
- 使用全价进行现金流折现和权重计算，净价用于报价展示；输入净价 / 全价均需明确转换。
- YTM 使用有界区间搜索结合二分或 Brent 类求根，返回收敛状态和回代残差；失败时不给近似成功结果。

2026-10-12 桌面反馈修订：参照用户通达信截图组织导航和表单，自动规则日程；增补负收益率、每年三付、同一定价导数凸性、到期一次付息与贴现债券的显式单利年化模型。只展示已实现计算类型：到期收益率、内在价值、修正久期、凸性。认购者/持有期收益率、浮动/差别利率与含权分支继续保留后续核验范围。截图用于交互参考，不证明算法与通达信一致。

### 5.4 国内债券

实现前交付独立规格：适用市场和券种、来源及日期、应计规则、付息日程、YTM 单利 / 复利分支、最后一期、闰年、兑付日顺延、净价 / 全价转换，以及各分支算例。

- 国内模式复用现金流与求根基础能力，但使用独立收益率口径，不是通用模式的中文别名。
- 用当前机构 / 交易系统计算说明与参考输出交叉确认。仅有价格、收益率而缺失票息、日程或结算信息的公开行情不能作基准。
- 历史标准可研究，但必须标注状态；没有核验来源的组合不得以“国内市场口径”开放。
- 若规则或参考样本获取未完成，通用试用版仍可交付；完整双口径交付保持未完成，不能默认降级成 Excel 算法。

### 5.5 久期与基点价值

常规多期、周期复利情形下，麦考利久期为折现现金流加权的年化时间；修正久期为其除以 `1+y/f`。定义与通用对照见 [Excel MDURATION](https://support.microsoft.com/en-us/excel/functions/mduration-function)。

实现要求：

- 在适用分支中用解析值；各分支均用定价导数作交叉校验。
- DV01 标为“收益率基点价值”，与收益率曲线平移风险分开。按中心差分 `-(P(y+h)-P(y-h))/(2h) × 0.0001` 估算，h 从 1bp 开始，并检查缩小步长后的稳定性。
- 同时显示每百元面值与指定持仓面值下的 DV01，明确货币单位；收益率上升对应价格变化的方向另行显示。
- 默认正现金流普通债券可显示正值基点价值，不使用绝对值掩盖异常定价导数。
- 凸性、关键期限久期和组合风险后续添加。

## 6. 技术落点

推荐在 Rust 共享核心实现唯一的计算引擎。金融数学本身无需工作区锁；只有已有笔记 / 配置写入才走原有锁与原子写入路径。

| 位置 | 拟议工作 |
| --- | --- |
| `crates/neopad-core/src/finance/` | 纯函数与类型，划分利率、TVM、日期、日程、债券、求根；不读写工作区 |
| `crates/neopad-core/src/lib.rs` | 导出金融请求、响应和计算接口 |
| `app/src-tauri/src/commands.rs` | 薄的计算命令桥接；确认文件现有结构后落入对应命令模块 |
| `app/src-tauri/src/lib.rs` | 注册命令 |
| `app/src/types/finance.ts`、`app/src/lib/invoke.ts` | 类型化请求 / 响应，不重复公式 |
| `app/src/composables/useFinancialTools.ts` | 面板状态、校验、结果失效、请求版本控制与插入目标保护 |
| `app/src/components/FinancialToolsPanel.vue` | 紧凑表单、结果和可折叠明细 |
| `app/src/components/EditorPane.vue` | 光标位置与文档版本保护的插入适配；已有 insertText 会替换选区，不能直接调用 |
| `app/src/App.vue`、`MenuBar.vue` | 入口与面板装配，保持计算和状态逻辑在独立模块 |
| `app/src/lib/keyboard-shortcuts.ts` 及测试 | Shift+F1、模态阻断、Esc、焦点与 Tab 行为 |
| `app/src/lib/i18n.ts`、`help-content.ts`、样式文件 | 文案、帮助和响应式布局 |

数值策略：首轮使用 Rust f64，计算途中保留精度，显示时舍入；金融利率与折现需要幂 / 对数，不因加入 decimal 就自动更准确。此工具用于测算；如以后要求合同逐期分币结算，应独立引入明确舍入规则与十进制金额模型。

默认显示金额 2 位、债券价格 6 位、利率百分数 6 位、久期 6 位；可复制完整精度。将计算口径与引擎版本写入完整记录。响应中的数值均应有限，错误使用明确代码和字段定位。

异步请求按输入版本识别，旧响应不得覆盖新参数。面板按需加载；首轮不增加第三方金融库、图表库或远程依赖。可在不修改 CLI 的情况下让 Rust 引擎为后续 CLI 复用预留条件，CLI 命令暂缓。

| M3 通用债券 | 日程、应计、价格 / YTM、久期、DV01 | 日期边界与最后一期样例；互算回代和导数检查通过 | 高 |

| M5 收尾验证 | 双语、明暗主题、最小窗口、文档与打包 | 完成双口径交付清单，发布前检查通过 | 中 |

执行依赖：M1 → M2 → M3；国内口径研究可在这些阶段持续推进，M4 以其规格完成为前提；M5 在两个模式均达到对应门槛后完成。

M2 和 M3 各提供一次可试用成果，避免等全部国内细节完成后才验证日常操作是否省事。本计划不承诺日历工期；国内参考资料的获取与实际对照是最大不确定性，M0 完成后再据明确分支估算。

## 8. 验收基准与测试

### 8.1 可立即使用的解析样例

### 8.2 外部基准

- 使用前述 Microsoft 官方样例验证金额、利率与债券价格显示；例如 FV 官方例子的期初月支付结果显示为 2,581.40。
- PRICE 官方例子显示 94.63；YIELD 官方例子显示 6.5%；MDURATION 官方例子显示 5.736。三个样例各自使用自己的输入，不能混为一只债券。
- 官方文档中的舍入结果只验证相应显示位数；高精度断言必须另有高精度参考计算与来源。
- 国内至少建立 12 个输入齐全的固定样例，覆盖年 / 半年付息、闰年、月末、付息日前后、最后一期和长剩余期限；来自当前算法说明或可复核参考计算，不以净价 / YTM 互算自洽替代外部校验。
- 通用和国内基准分别标记，差异记录原因；不能对不同口径要求数字一致。

### 8.3 数值与行为验收

- 高精度基准的每百元价格误差目标不超过 1e-6；YTM 绝对误差目标 1e-8（小数单位），并满足价格回代误差；久期误差目标 1e-6 年。仅有舍入外部数据时按其有效精度验证，不能声称达到了这些高精度目标。
- 验证 PV / FV 反向关系、零利率极限、正现金流债券价格随收益率下降而上升、面值线性缩放、净价 + 应计 = 全价、久期 / DV01 与定价导数一致。
- 覆盖极小 / 零 / 允许的负利率、超长周期、溢出、非法日期、闰日、月底日程、结算日等于到期日、求根区间失败和不收敛。
- 仅在适用公式分支中断言“平价票息 = 收益率”等性质；不将多期性质强加给特殊最后一期。
- 拒绝解析代码围栏或任意文本为金融输入；没有 eval、AI 公式生成或静默猜测单位。
- 输入修改使旧结果失效，晚到响应不回写；一次插入可一次撤销，选区原文不丢失；外部笔记修订冲突继续由现有路径保护。
- 420 × 360 / 720 × 520、明暗主题、中英切换、键盘操作、Vim 模式、编辑 / 分屏 / 预览、Esc 优先级均检查。

```powershell
cargo fmt --check

pnpm build
pnpm tauri:build
```

增加针对金融面板的桌面交互用例；若变更 CLI，追加 `cargo build -p neopad-cli --release` 与 CLI 行为测试。

## 10. 完成定义与后续

首轮完整完成条件：资金工具、通用债券和经过核验的国内债券均可离线使用；口径和结果可复核；能够复制 / 安全插入 Markdown；测试、桌面关键流程与打包通过。

通用试用版的完成不等于国内模式完成。贷款、回购与凸性已实现。本轮增加整笔债券持有期收益分解，以及一次变号现金流的 XIRR；多次变号、分批买卖、券种规则、临时方案比较和 CLI 接口仍需按实际使用记录另行评估。
